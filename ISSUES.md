- Password detection: When UI Automation lookup fails, the current fallback assumes an ordinary field. This deserves hardening, especially when typing logs are enabled. That behavior was inherited from C++.
- Occasional stalls: UI Automation uses STA workers, while Microsoft recommends MTA for this usage. Logging also performs some disk writes in keyboard processing. These are review concerns for slow applications and heavy system load. Microsoft threading guidance ([https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading))
- Lifecycle and deployment: Sleep/resume, keyboard-layout changes, long sessions, startup registration and installer/update behavior still need targeted Windows testing. Existing auto-switch ambiguities also remain.
